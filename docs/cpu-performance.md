# CPU 异常修复与验证

## 问题

`Gateway.snapshot()` 原来在主线程遍历每个账号的五小时、周额度历史。每条请求又扫描完整模型价格目录进行字符串标准化、匹配和排序。桌面每次刷新完成后等待 1.5 秒再次获取快照，导致成本约为“历史记录数 × 目录大小”。已有的数据库记录缓存不能避免这部分计算。

## 修复

- 为批量计价建立模型 ID、显示名称、手动价格和账号索引。按现有规则处理数字版本、供应商优先级、歧义、手动关联、零价格、币种及上游已报告费用。解析器属于一份价格配置，不按可变数组的对象身份进行全局缓存。
- 周期统计由长期运行的 `quota-statistics-worker` 执行，通过只读 SQLite 事务获取一致的历史数据。主线程快照读取缓存，首次计算或输入失效时显示更新状态。
- 队列限制为一个执行任务和一个最新待执行任务。账号历史、额度观察、价格变更或周期到期使结果失效；旧版本、已删除账号以及过期周期的结果不写回。配置保存异步等待统计，不阻塞网关事件循环。
- 周期均值仍通过原数据库写入入口保存，保留观察时间顺序与排除周期语义。无变化的快照不再执行这部分 SQL。
- 价格配置通过版本号发送给统计 Worker，桌面轮询仅在版本变化时通过 IPC 发送目录。用量查询在数据库、价格、查询参数均未变化时复用结果；热力图考虑跨日、未来记录和系统时钟回拨。
- 隐藏和最小化窗口暂停展示轮询，恢复时立即刷新。使用 Electron 原生窗口状态，避免把 macOS 窗口遮挡误判为用户隐藏窗口。后台网关及账号维护继续运行。
- 请求列表与价格列表也复用批量解析器，费用明细保持原有算法。

## 可复现验证

所有基准使用临时目录和合成数据，不读取安装版凭据、修改用户历史或调用真实模型。

```sh
npm run test:unit
npm run test:smoke
npm run test:cpu
# 先构建，再分别测量真实 Electron 可见、隐藏窗口各 60 秒。
npm run build
NAVO_PERF_SAMPLE_MS=60000 node scripts/cpu-performance.mjs --electron --skip-baseline
# 十倍历史规模、目录达到当前允许的最大规模。
NAVO_PERF_RECORDS=20000 NAVO_PERF_CATALOG=50000 node scripts/cpu-performance.mjs --skip-baseline
```

GUI 测试应串行运行，避免不同应用实例抢占焦点导致悬浮提示测试失败。

2026-09-22，本机 macOS ARM64 测量：

| 指标                     | 2,000 条历史 / 8,000 项目录 | 20,000 条历史 / 50,000 项目录 |
| ------------------------ | --------------------------: | ----------------------------: |
| 原计价函数单次批量计算   |                 约 7,975 ms |                  未运行原算法 |
| 建立索引并完成批量计价   |      约 17 ms；另一次 29 ms |                     约 194 ms |
| 热缓存快照 P95           |                  约 0.24 ms |                    约 0.25 ms |
| 统计更新时 HTTP 请求 P95 |                   约 3.8 ms |                     约 5.8 ms |
| 事件循环延迟 P95         |                  约 11.2 ms |                    约 11.2 ms |

2,000 条历史下，真实 Electron 主进程（包含 Worker）的进程 CPU 时间增量测量：可见窗口平均约 0.71%，隐藏窗口约 0.45%，各采样 60 秒。这不是安装版 PID 的原地修复数据，也不是两小时稳定性测试。

原算法与索引算法逐条对比完整计价结果。回归测试另外覆盖缓存失效、周期排除、观察时间边界、任务合并、删除账号、退出清理、Worker 故障恢复、多个账号更新隔离和乱序 IPC 响应。性能数字用于同机复测，自动化同时检查“重复调用不再次扫描目录、不重复写周期”，避免只依赖耗时阈值。

验证结果：320 项单元测试通过；完整 Electron 界面、托盘、会话迁移以及打包应用的凭据、重启、转发、历史和仪表盘资源测试通过。同步更新了滚动数字的无障碍测试选择器，并将休眠租期测试的启动准备与过期恢复验证分开，避免在准备阶段提前耗尽短租期。

本次测量另存为 `artifacts/cpu-electron.json`、`artifacts/cpu-stress.json`；单元测试和界面测试日志为 `artifacts/cpu-unit.log`、`artifacts/cpu-smoke.log`。重新运行基准默认写入 `artifacts/cpu-performance.json`。生产修复不新增 Redis、配置文件格式迁移或外部服务依赖。
